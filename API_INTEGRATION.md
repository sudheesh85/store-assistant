# API Integration Guide

This document explains how the React frontend communicates with the FastAPI backend that powers the Malayalam + English NL2SQL experience for Kerala SMB retailers.

> **Base URL** (local development): `http://localhost:8000/api`
>
> Adjust the base URL to match your deployment host.

---

## 1. Health

**Endpoint**: `GET /health`

Simple availability check used by the frontend while bootstrapping. Returns:

```json
{
  "status": "ok"
}
```

---

## 2. Dataset Lifecycle

Uploaded CSVs are merged into a single SQLite database per store (default store id `demo-store`). Each upload is tagged with a `dataset_type` (`sales`, `inventory`, `staff`, `transactions`) and the backend preserves column descriptions so the NL2SQL prompt is grounded in business context.

### 2.1 Upload CSV

**Endpoint**: `POST /datasets/upload`

**Content-Type**: `multipart/form-data`

**Form fields**:
- `file` *(required)*: CSV exported from POS/ERP
- `dataset_type` *(required)*: One of `sales`, `inventory`, `staff`, `transactions`
- `store_id` *(optional)*: Store identifier. If omitted, the backend uses `demo-store` (auth will supply this later)
- `column_descriptions` *(optional)*: JSON object with overrides for column descriptions

**Response** `200 OK`:
```json
{
  "dataset": {
    "dataset_type": "sales",
    "table_name": "sales_raw",
    "row_count": 4821,
    "source_file": "nov_sales.csv",
    "uploaded_at": "2025-11-12T09:15:23.417Z",
    "columns": [
      {
        "name": "invoice_id",
        "original_name": "Invoice ID",
        "dtype": "text",
        "description": "Unique invoice number generated by the POS system",
        "sample_values": ["INV-1001", "INV-1002"]
      },
      {
        "name": "net_sales",
        "original_name": "Net Amount",
        "dtype": "number",
        "description": "Line-level sales amount after discounts (INR)",
        "sample_values": [1500.5, 2340.0]
      }
    ]
  }
}
```

**Errors**:
- `400`: invalid file or parsing failure
- `400`: file larger than `MAX_UPLOAD_MB`

### 2.2 List Datasets

**Endpoint**: `GET /datasets`

Returns all datasets registered for the store (same shape as the upload payload, wrapped in an array). Pass `store_id` as a query parameter to target a specific tenant.

```json
{
  "store_id": "demo-store",
  "datasets": [
    { "dataset_type": "sales", "table_name": "sales_raw", "row_count": 4821, "columns": [...] },
    { "dataset_type": "inventory", "table_name": "inventory_raw", "row_count": 640, "columns": [...] }
  ]
}
```

### 2.3 Fetch Schema

**Endpoint**: `GET /datasets/{dataset_type}`

Optional query param: `store_id`.

Response combines metadata plus a human-readable schema string used when crafting prompts.

```json
{
  "dataset": { ... },
  "schema_text": "Table: sales_raw\n- invoice_id [text] – Unique invoice number generated by the POS system (examples: INV-1001, INV-1002)\n- net_sales [number] – Line-level sales amount after discounts (INR) (examples: 1500.5, 2340.0)"
}
```

### 2.4 Delete Dataset *(optional)*

**Endpoint**: `DELETE /datasets/{dataset_type}` (optional `store_id` query param)

Removes the raw table and registry entry for the given dataset type.

```json
{
  "success": true,
  "dataset_type": "sales"
}
```

## 3. NL2SQL Ask

Translates a Malayalam, Manglish, or English question into SQL, executes it, and returns table/chart-friendly results plus an optional natural-language explanation.

**Endpoint**: `POST /nl2sql/ask`

**Request Body**:
```json
{
  "question": "ഇന്നത്തെ മൊത്തം വിൽപ്പന എത്ര?",
  "store_id": "demo-store",
  "dataset_type": "sales"
}
```

**Successful Response** `200 OK`:
```json
{
  "question": "ഇന്നത്തെ മൊത്തം വിൽപ്പന എത്ര?",
  "store_id": "demo-store",
  "dataset_type": "sales",
  "sql": "SELECT sold_at AS date, SUM(net_sales) AS value FROM sales_raw WHERE date(sold_at) = date('now') GROUP BY date",
  "result": {
    "columns": ["date", "value"],
    "rows": [["2025-11-12", 54320.75]],
    "returned_rows": 1,
    "truncated": false
  },
  "explanation": "ഇന്ന് മൊത്തം വിൽപ്പന ₹54,321 ഓളം ആയി. ഇത് ഇന്നലെക്കാൾ 12% ഉയര്‍ച്ചയാണ്.",
  "visualization": {
    "type": "line",
    "config": {
      "x": "date",
      "y": "value"
    }
  }
}
```

**Error Response**:
```json
{
  "question": "Show me staff attendance",
  "store_id": "demo-store",
  "dataset_type": "sales",
  "error": "Unable to parse SQL from model output"
}
```

Notes:
- `sql` is only present when generation succeeds.
- `explanation` is returned only when `ENABLE_RESULT_EXPLANATION=true` **and** an OpenAI key is configured.
- `visualization` may be `null` when the heuristic cannot detect a chart.

## 4. Manual SQL Execution

Use this when the frontend allows power users to tweak the generated SQL or run saved queries.

### 4.1 Execute

**Endpoint**: `POST /query/execute`

**Body**:
```json
{
  "store_id": "demo-store",
  "sql": "SELECT category, SUM(net_sales) AS value FROM sales_raw GROUP BY category ORDER BY value DESC"
}
```

**Response**:
```json
{
  "store_id": "demo-store",
  "sql": "...",
  "result": {
    "columns": ["category", "value"],
    "rows": [["Staples", 23000.0], ["Beverages", 12050.2]],
    "returned_rows": 2,
    "truncated": false
  }
}
```

Validation rules:
- Only `SELECT`/`WITH` queries are allowed.
- No semicolons, DDL, or DML keywords permitted.
- Results are capped to `MAX_ROWS` rows; `truncated=true` signals the cap was hit.

### 4.2 Validate

**Endpoint**: `POST /query/validate`

Returns `{ "is_valid": true }` when the statement passes guardrails. When invalid:

```json
{
  "is_valid": false,
  "error": "Only SELECT queries are allowed"
}
```

## 5. Authentication & CORS

The sample backend ships without authentication. Plug in your preferred auth layer (API key, JWT, Firebase, etc.) and protect the routers using FastAPI dependencies. Update `ALLOWED_ORIGINS` in `.env` to match frontend hostnames.

```env
ALLOWED_ORIGINS=http://localhost:3000,https://storebot.example.com
```

---

## 6. Environment Variables

| Variable | Default | Description |
| --- | --- | --- |
| `OPENAI_API_KEY` | – | Required for NL2SQL + explanation |
| `OPENAI_MODEL` | `gpt-4o-mini` | Chat model used for SQL + summaries |
| `OPENAI_TEMPERATURE` | `0.0` | Controls creativity of SQL generation |
| `DATA_STORAGE_PATH` | `./storage` | Directory where SQLite DBs and registry live |
| `MAX_UPLOAD_MB` | `25` | Upload size limit per CSV |
| `MAX_ROWS` | `1000` | Row cap per query response |
| `ENABLE_RESULT_EXPLANATION` | `true` | Toggle Malayalam/English explanation |
| `ENABLE_VISUALIZATION_SUGGESTIONS` | `true` | Toggle chart heuristics |

---

## 7. Frontend Expectations

- Expect responses in under ~5 seconds for typical datasets (~10k rows).
- When `truncated=true`, show a note in the UI (“Showing first 1000 rows”).
- Use `visualization.type` + `visualization.config` to choose chart components (`bar`, `bar_horizontal`, `line`, `pie`, `scatter`, `metric`).
- Voice features (speech-to-text / text-to-speech) are handled entirely on the frontend; backend returns plain JSON only.

## 8. Quick Test Snippets

```bash
# Upload a CSV
echo "date,sales\n2025-11-10,1200" > sample.csv
curl -X POST http://localhost:8000/api/datasets/upload \
  -F "file=@sample.csv" \
  -F "dataset_type=sales" \
  -F "store_id=demo-store"

# Ask a Malayalam question
curl -X POST http://localhost:8000/api/nl2sql/ask \
  -H "Content-Type: application/json" \
  -d '{
        "question": "ഇന്നലെ ഏറ്റവും കൂടുതലായി വിറ്റ ഉൽപ്പന്നം ഏത്?",
        "store_id": "demo-store",
        "dataset_type": "sales"
      }'

# Run manual SQL
curl -X POST http://localhost:8000/api/query/execute \
  -H "Content-Type: application/json" \
  -d '{
        "store_id": "demo-store",
        "sql": "SELECT sale_date, SUM(net_sales) AS value FROM sales_raw GROUP BY sale_date"
      }'
```
